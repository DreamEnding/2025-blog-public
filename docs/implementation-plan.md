## 1. 目标与交付范围

基于当前项目建设部署在用户自己服务器上的文档站，主要服务已有 API 用户，帮助他们找到接口示例并成功调用。

- 所有文档和文章公开阅读，仅管理后台需要登录。
- 允许使用 GitHub 管理源码及部署；网站运行、日常内容编辑和发布无需访问 GitHub。
- 管理员直接通过网页后台维护内容，发布后生效，无需重新构建或部署。
- 本次交付代码、必要测试、Docker Compose 配置与部署说明，完成本地验收；不包含实际服务器部署。
- API 文档正文由用户编写，本次提供结构与编辑展示能力。

## 2. 当前项目基础

前期只读检查得到以下事实，实施时按需核对具体代码：

- 使用 Next.js 16 App Router、React 19、TypeScript 和 Tailwind CSS 4。
- 现有文章存储于 `public/blogs/`，使用 Markdown、元数据 JSON 和索引文件。
- 已有网页编辑器、Markdown 预览、图片上传、代码高亮、公式渲染与文章内部目录。
- 现有在线发布通过 GitHub API 提交内容，再等待重新部署；需要改为服务器直接存储和发布。
- 当前站点以个人博客为主要结构，需要增加分层文档导航、全文搜索和文档阅读布局。
- 原有点赞、字体及统计存在外部服务引用，实施时检查并处理与新站相关的旧入口和引用。
- 根目录未发现 `.codegraph/`，不进行索引创建。

## 3. 已确认的产品需求

### 3.1 首页与阅读页面

- 使用简洁的导航首页，突出快速开始入口和搜索。
- API 文档、使用教程、模型选择是主要入口；技术分享和求职面经位于次要位置。
- 文档页面采用左侧分层导航、中间正文、右侧本页目录的布局。
- 适配电脑与手机。
- 支持 Markdown、图片、代码高亮及代码复制，复用现有编辑与渲染能力。
- 提供可复制的调用示例，不包含在线填写 API Key 并发送请求的调试功能。

### 3.2 内容栏目与组织

初始栏目：

1. API 文档
2. 使用教程
3. 模型选择
4. AI 技术分享
5. 求职面经

- 前三个栏目支持分组和子文档，文档手动排序。
- 后两个栏目以文章列表展示，按发布时间倒序。
- 后台支持栏目和文档的创建、重命名、排序、移动与删除。
- 删除非空栏目时，要求先处理其中的内容。
- 从空内容开始，移除原博客文章和不相关入口，保留必要的空状态与编写提示。

### 3.3 管理后台与发布流程

- 单管理员账号密码登录，不开放注册。
- 初始管理员凭据通过部署配置设置。
- Markdown 编辑与预览，支持图片上传和代码块。
- 支持保存草稿、预览、发布和撤回发布。
- 编辑已发布内容时，保存只更新草稿；点击发布才对公开版本生效。
- 支持恢复上一次发布版本。
- 草稿不得通过公开页面、公开内容接口或搜索结果泄露。

### 3.4 搜索

- 搜索所有已发布文档和文章的标题、摘要与正文。
- 搜索结果展示所属栏目和匹配片段。
- 发布、撤回或删除内容后，搜索结果同步反映公开内容状态。

### 3.5 站点设置

后台可维护：

- 网站名称与 Logo。
- 首页介绍。
- 控制台、获取 API Key 等外部入口链接。

首页采用固定结构，首版不包含自由拖拽布局编辑器。

### 3.6 备份与恢复

- 后台提供一键导出备份和从备份恢复。
- 备份包含文档、栏目、站点设置及上传图片。
- 恢复前明确提示覆盖范围，并要求确认。
- 导出的备份能够恢复到空实例，用于迁移和灾难恢复。

## 4. 已确认的技术方案

- 延续现有 Next.js 项目，复用编辑器和 Markdown 渲染能力。
- 内容及站点设置使用 SQLite 保存。
- 图片保存到服务器目录。
- 数据库和图片通过 Docker 卷持久化，容器重建后仍然保留。
- 使用 Docker Compose 部署。
- 内容发布直接作用于服务器数据，不依赖 GitHub 提交或应用重新部署。
- 首版采用中文界面、单套文档，不包含多语言、API 多版本管理、多人角色或审核流程。

具体数据库结构、认证实现、搜索实现及备份格式在编码时确定，遵循简单、可靠、便于维护的原则，不为假设中的未来需求增加抽象层。
